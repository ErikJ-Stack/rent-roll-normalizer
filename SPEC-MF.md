# SPEC-MF — Multifamily (MF) product line

> The MF product line is the multifamily / conventional-apartments counterpart
> to the ALF (senior-housing) product. It is being built in phases; this spec
> grows as those phases land. See CLAUDE.md ("Two product lines") for the
> phasing and the `mf_` naming convention.

**Status:** Phase 0 of MF Track 4 (UW Model mapping) shipped 2026-06-03. The MF
RR/T-12/AR parsers (P1–P2), OM extraction (P3), and MF Analyzer (P4) are not yet
built. MF has **no Analyzer substrate** and shares none of the ALF
care/payer/acuity data model — it is units / floorplans / leases.

---

## 1. MF UW Model mapping (Track 4 — Phase 0)

### 1.1 What it is

The **MF UW Model** (`MF_UW_Model_v15.xlsx`) is the downstream per-deal
multifamily acquisition underwriting model — the MF counterpart of the ALF UW
Template. It is authored externally by the operator in Excel; Claude Code owns
the **mapping registry** and (in a future phase) the parser/writer.

The committed reference copy lives at `assets/MF_UW_Model_v15.xlsx`. The
operator's canonical copy lives at
`Deals/Acquisition/_Template/MF Templates/MF_UW_Model_v15.xlsx`.

### 1.2 Model shape (v15)

23 sheets. The full model spans Cover, Inputs, Prop Info, Data Refresh, Data
Checklist, Scenarios, Acquisition Costs, T-12 Analysis, Recapture & Upside,
Rent Roll Analysis, P&L, Lease-Up & Capital Call, Loans, Rental Comps, Capex,
Payroll, Waterfall, Exit Strategy, XIRR Analysis, Sensitivity, LP Return
Illustration, Portfolio Rollup, and a hidden `_StdCOA`.

Only **two sheets are data-intake targets** — everything else is analyst-driven
assumptions or formula-derived analytics:

**Path 1 — Rent Roll → `Rent Roll Analysis` grid**
- Header row 272; paste anchor `A273`; data rows 273–1772 (1,500-unit capacity).
- 37 columns A–AK: identity (A Bldg, B Unit#, C Type, D SF, F Resident), status
  (E Status, G Legal — boolean from a `**` resident-name prefix), dates (H–K),
  rates (L Mkt / M Actual / N Sched / P Deposit), AR (O Balance, Q–T aging),
  U Status Flag, V Notes, and W–AK per-unit ancillary income breakouts.
- Rows 1–271 are formula-derived diagnostic dashboards; the writer must not
  overwrite them.

**Path 2 — T-12 → `T-12 Analysis` Layer 1**
- Header row 105; paste anchor `A106`; data rows 106–255.
- Cols: A Acct#, B Account Name (raw), C–N 12 monthly, O T-12 Total (template
  `=SUM`), **P → MAPPING** (`_StdCOA` bucket string).
- Col P drives every Layer-3 SUMIFS aggregation — the intelligence layer, the MF
  equivalent of ALF's `Description_Map`. Rows 1–101 + 257–262 are
  formula-derived; the writer must not overwrite them.

**`_StdCOA`** is the bucket master list (18 expense + 26 income buckets). Col F
lists the PSI source account numbers per bucket — the seed for a future
COA→bucket dictionary.

### 1.3 Source side (operator intake docs)

MF has no Analyzer; the mapping sources directly from the raw operator exports
in `MF Docs/` (gitignored). Sample property: Hidden Lakes Apartments (143 units,
Atlanta MSA).

| Doc | Format | Feeds |
| --- | --- | --- |
| `RR-Hidden-Lakes-*.xlsx` | Yardi-CIM "Rent Roll - Cim" | RR grid cols A–P |
| `AR-Hidden-Lakes-*.xlsx` | Resident Aged Receivables | RR grid cols Q–T + V (Bldg-Unit join) |
| `Sortable-RR-Hidden-Lakes-*.xlsx` | redIQ export (Source Data charge codes) | RR grid cols W–AK ancillary breakouts |
| `T12-NOI-Hidden-Lakes-*.xlsx` | PSI T-12 Income Statement (Cash Basis) | T-12 Layer 1 cols A,B,C–N |

### 1.4 Registry

`tools/mf_uw_template/registry.json` (schema `mf-uw-mapping/v1`) keys semantic
concepts to version-keyed model targets (`templates.v15`). 46 concepts across
three paths: `metadata` (4), `rent_roll` (37), `t12` (5). Status rollup at
v0.1.0: 19 `mapped` / 5 `proposed` / 21 `gap_source` / 1 `derived`.

Artifacts are regenerated by
`python tools/mf_uw_template/build_mapping_artifacts.py`:
`MAPPING_TRACKER.md`, `mapping_tracker.csv`, `mapping_mindmap.html`.

### 1.5 Gaps (deferred to the MF parser build, P1–P2)

Everything requiring parser intelligence sits at `gap_source`:

- **T-12 col-P `_StdCOA` mapping** — needs a PSI-account → bucket dictionary
  (future `mf_mappings.py`, seeded from `_StdCOA` col F).
- **AR aging (Q–T)** — separate AR doc, joined on Bldg-Unit; period-mismatch
  caveat (RR Apr 2026 vs AR Mar 2026).
- **Ancillary breakouts (W–AK)** — only the redIQ Sortable-RR `Source Data`
  charge-code grid carries per-fee detail.
- **Status taxonomy / Legal flag** — normalize operator status strings to the
  model's COUNTIF wildcard vocabulary; derive Legal from the `**` name prefix.

### 1.6 Ownership & handoff

The model is authored externally in Excel; Claude Code owns the registry +
(future) writer. Model-side change requests are produced as handoff briefs under
`tools/mf_uw_template/handoffs/` and indexed in
`tools/mf_uw_template/HANDOFF_TRACKER.md`. Do not round-trip the model through
openpyxl / Google Sheets / LibreOffice (drops `xl/metadata.xml` dynamic-array
parts and corrupts formulas — openpyxl quirk #6 in CLAUDE.md).
